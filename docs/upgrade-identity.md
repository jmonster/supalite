# Identity columns during `lite upgrade`

The published Lite 0.11.0 exporter reconstructs application schema from
`information_schema.columns` but omits identity metadata. Identity fields become
plain integers in the reconstructed schema. Two consequences are reproducible
with ordinary SDK inserts on both the Node SQLite and PGlite drivers:

- `GENERATED ALWAYS AS IDENTITY` replay fails with PostgreSQL `428C9` because the
  exported INSERT supplies the existing ID without `OVERRIDING SYSTEM VALUE`.
- `GENERATED BY DEFAULT AS IDENTITY` replay imports ID 1, but emits no identity
  sequence reset. The next default-generated INSERT fails with `23505`.

## Focused fix

`upstream/lite-0.11.0/dist/cli/upgrade-identity.js` preserves identity generation mode and options through
catalog reconstruction. The upgrade schema retains that mode from the parsed
reconstructed AST, so intervening `ALTER TABLE` migrations are respected.
Only INSERTs containing an ALWAYS identity receive `OVERRIDING SYSTEM VALUE`.
Computed columns remain omitted, IDs remain unchanged, and the existing foreign
key ordering is retained.

Identity resets read the target's `pg_sequence` settings. They choose the first
configured increment beyond imported IDs in the sequence's direction, at or
beyond its start. An empty, unconsumed target identity retains its configured first value. Numeric SQL
arithmetic avoids bigint overflow; exhausted sequences remain exhausted and the
next INSERT raises native `2200H`. Nonempty cycling identities explicitly fail
with `0A000`, rather than claiming collision-free continuation after wraparound.

Ordinary serial/bigserial export and reset logic is unchanged. This fix does not
preserve the exact source sequence counter after deletions, cached/aborted
allocations, or `setval`; it restores safe row-based continuation on a fresh
migration target. It does not add SQLite support for custom sequence options or
non-primary-key identity auto-increment. Existing `ON CONFLICT DO NOTHING`
behavior and general identifier/value serialization are outside this change.

## Verification

Run `bun install --frozen-lockfile`, then `bun test --bail --timeout 60000 test/upgrade-identity.test.mjs test/upgrade-identity-sequences.test.mjs`. Tests replay exported SQL on fresh PGlite:

- Both drivers verify that omitting the override/reset reproduces the errors, then preserve IDs, FK links,
  computed values, ordinary serial SQL, and successful next generated IDs
- PGlite-source custom increments, ascending/descending bounds, empty tables,
  exhaustion, and explicit rejection of CYCLE
- Direct reset SQL covers off-increment and out-of-range explicit IDs, bigint
  boundaries, and quoted names
- Catalog reconstruction follows `ALTER TABLE` identity changes

These are local exporter/SQL replay tests, not a full Supabase upgrade run.
